# Método de creación y límites

Se aplicó skill-creator-z a cada una de las quince responsabilidades. El método del entorno del autor se identifica por nombre y SHA256 en creator-record.json; no es una dependencia necesaria para consumir las skills publicadas.

1. Se extrajo intención, contrato, alternativas y criterios por skill en plan.json.
2. Se consultaron fuentes primarias y alternativas; la investigación común se reutilizó, con límites de actualidad por fuente.
3. Se ejecutaron quince ejercicios baseline antes de redactar los SKILL.md. Eran respuestas competentes; no se forzó un RED ficticio. El juez detectó algunas omisiones al comparar después.
4. Se redactaron quince paquetes con fuentes, riesgos, casos, contrato y procedimiento.
5. Se repitieron quince ejercicios con las skills y se revisaron de forma independiente comportamiento, activación y permisos/generalización.
6. Se conservaron los hallazgos iniciales. Descripciones refinadas en 0.1.1; preflight de ingesta refinado en SK03 0.1.2. Casos de frontera y reensayos separados.

No se presenta el trabajo como strict ni producción. El baseline y candidato usaron agentes del mismo entorno, no evaluadores humanos; hay una respuesta por caso y contexto compartido dentro de cada grupo de cinco. Coste y tokens no disponibles. No se certificaron todos los runtimes ni proveedores.

La publicación es una biblioteca de procedimientos y plantillas. Una invocación real debe aplicar las skills al repo y entorno del nuevo caso y producir su propia evidencia de implementación y despliegue.
